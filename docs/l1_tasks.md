# L1 刚性操作任务

目标是在固定传感器、动作接口和运动执行器条件下，评估 GPT 的视觉理解、空间判断、操作决策与失败恢复。实现依据飞书任务文档第 111 版的 L1-01～L1-08；L1-09 不在本轮范围。下列尺寸和阈值是本项目的工程基线，并非飞书文档规定的数值。

当前八项任务统一使用 `lab_room_v1` 室内环境和 `r5_black_silver_v1` 机器人外观。
其背景、材质和照明构成新的观测条件；比较实验时须固定这两个配置，不能与旧白底
场景直接合并统计。资产来源、启动与恢复旧外观的方法见 [场景外观说明](simulation_appearance.md)。

## L1-01 宽容间隙版

- 圆柱约 60 g，上下统一直径 35 mm、高 60 mm，使用单个圆柱碰撞体，无粗头、台阶或正反端区别。夹爪最大开口 70 mm，居中张开接近时两侧各有约 17.5 mm 几何余量。初始平底竖放，未被抓住；仍可能被撞倒，没有固定或吸附。
- 单孔直径 55 mm、深 20 mm、底板厚 5 mm；单侧间隙 10 mm。落座后圆柱高出孔口 40 mm，为抓持和撤离留出空间。32 段切向壁体围成真实开口，不用封住孔洞的单个凸包。
- 夹爪/圆柱销、桌面/圆柱销保留静动摩擦 0.8。孔座材质静动摩擦为 0，两侧材质均使用 `min` 合成，保证插入接触有效摩擦为 0。保留重力、法向碰撞与底部支撑；没有吸附或任务动作脚本。
- 默认固定起点；模型自行判断物体位置、抓点、对准及路径，抓持应留出插入端和夹指对孔口的间隙。该版不考察从横放状态翻转工件、正反端辨认或力调节。
- 成功要求先形成抓取抬升证据，再在双指持握时达到 15 mm 深度。末态必须满足轴线偏差不超过 10°、进入孔口的圆柱截面被容纳、上端露出孔口、未穿透底板。轴向旋转和两端对调均等价；水平躺放不能通过。几何判定允许 0.5 mm 数值接触容差；不要求距唯一目标中心小于 3 mm。
- 释放后要求孔座接触合力至少为重量的一半，且没有有效桌面支撑；再结合公共撤离和 1 s 稳定判据。掉进孔内但没有持握插入过程、悬空、搁在孔边或穿底均不能通过。
- `criteria` 保存实际深度、轴线偏差、孔内容纳、持握插入和支撑证据；`stage` 区分抓取抬升、对准插入、释放撤离和稳定阶段。评分读取仿真真值，模型不可读取这些评分字段。

## Prompt 组织

共享系统说明包含动作接口、三路观测、主动换视角和通用操作指导，例如物体相对 TCP 的偏移、持续检查抓持、接触附近的小步修正以及拒绝/超时后的状态核对。每次搬运或插入前应重新确认物体仍在手中；掉落后不能继续使用旧的物体相对 TCP 偏移。所有任务共用 `shared_operation_notes_task_goal_v3`，不按任务切换攻略。

配置了观察臂时，提示模型在看不清抓持、工作端、目标孔口或相对对准关系时主动换视角，也包括无法确认物体仍被抓住、无法判断接近或插入失败原因的情况。先确认操作臂处于稳定姿态，再单独移动观察臂，保持操作臂及其夹爪不变；取得新画面和执行反馈后继续操作，并在决策笔记中说明本次观察要消除的疑问。现有视角足够时无需移动。该行为由模型决定，不是自动跟随或固定观察轨迹；观察臂角色限制和共享预算保持不变。

L1 配置只写角色、任务目标及成功要求；几何公开尺寸由场景定义生成，不向模型提供物体坐标、正确抓点或参考轨迹。完整实际系统说明保存在每次运行的 `policy_configuration` 中，最终任务指令保存在 `instruction.txt`。这属于带通用操作指导的自定义评测条件，不能与提示条件不同的结果混合统计。

## 固定条件与信息边界

L1-02～L1-08 的任务设计沿用 master；L1-01 采用上述宽容版本。执行条件统一使用当前公共流程。

- 配置引用 `configs/workflows/gpt_default.toml`：medium、最多 100 次决策、总控制周期与墙钟时间不限，物理步长 1/240 s、控制步长 1/12 s。等待模型时暂停物理推进。每条动作仍有预算；未成功的停止请求会被拒绝并计入总调用数，成功、耗尽预算、手动中断或不可恢复故障时结束。
- 左臂操作；右臂可移动腕部相机观察，但不能接收夹爪命令，也不得接触、推拉或支撑物体。观察动作共用模型调用与时间预算，评分不把合法观察臂移动当成固定臂漂移。
- 固定提供三路 RGB-D、虚拟相机内外参、坐标/TCP 标记、机器人实测状态、执行反馈和本回合文字历史；支持像素深度查询和决策笔记。不使用检测器或物体真值生成动作。
- 使用公共 `sparse_eef_normalized_gripper` 协议与 cuRobo 轨迹规划；组合动作先跟踪关节路径，再控制夹爪。gripper=0 闭合、1 张开、null 保持目标。闭合受阻可结束闭合动作，但不能认定抓取成功。
- 首次 GPT 观测前，左臂执行固定朝下准备动作，TCP 相对基座 `(0.36, 0, 0.21)` m，当前对应世界 `(0.36, 0.42, 0.25)` m；保持夹爪开口；右臂移向两臂之间，腕部相机朝向左臂工作区。标准安装下右腕光心目标为世界 `(0.28, -0.10, 0.50)` m，视线对准左臂准备位姿下方的固定区域；相机目标通过安装外参转换成 TCP 目标，由公共 cuRobo 执行。初始化不读取工件位置、不计入模型决策或执行动作数，消耗记录的仿真与现实时间，并单独记录/录像。准备失败不进入模型决策。若任务启用失败复位，同样先完成准备再重新观测。
- 物体与目标位姿、接触点和评分不进入模型输入。规划器额外读取静态碰撞几何，以及双指接触物体的实测位姿和表面，用于搬运净空检查；这是规划层的仿真真值权限，需要与旧 IK 条件分别统计。右臂避免接触仍依赖模型遵守指令，当前未实现覆盖全臂的接触违规检测。

`specs.py` 定义形状和任务目标；`scene.py` 负责构建、复位和测量；`evaluation.py` 独立评分；`task.py` 接入公共执行循环。任务只配置实验参数，不增加操作逻辑开关。

## 复位与评分

每次复位使用 `[runtime].seed`。L1-01 默认关闭位置和偏航抖动，正式布局扩展可在易达范围内启用；其余任务起点 XY 默认抖动 ±8 mm、偏航 ±0.15 rad。夹具位置固定。相同种子复现相同初始布局，不承诺跨操作系统的 PhysX 轨迹逐位相同。

每个操作物体都必须出现持续至少 0.25 s 的双指接触，且物体中心比初始位置升高至少 15 mm。接触力阈值为每指 0.05 N。这样只推入目标或工程检查直接设置目标位姿不会算完整任务成功。

需释放的任务要求双指无有效接触、夹爪实测宽度至少 60 mm，并且 TCP 与物体包围盒间距至少 65 mm。指令要求打开到 70 mm。各目标同时满足以下条件持续 1 s 才成功：

- 目标几何成立、抓取抬升过程证据成立、释放条件成立（L1-05 除外）。
- 物体线速度不超过 0.02 m/s、角速度不超过 0.2 rad/s。
- 如配置了固定臂，其关节漂移不得超限；当前右臂是观察臂，不受固定臂漂移限制。

L1-01 按孔内容纳、深度和支撑评分，轴向旋转不影响判断。其余插入类默认 XY 误差不超过 3 mm、高度误差不超过 4 mm、姿态误差不超过 0.14 rad。积木条纹允许 180° 对称；工具和积木采用 10 mm 平面位置容差。环还要求挂钩位于环孔内且挂钩接触合力至少为环重量的一半。薄片检查跨越狭缝平面的角点轨迹和最终整体容纳状态。

`goal_complete` 与 `process_constraints_met` 分开记录。模型宣称完成不代表成功；未完成即停止或用尽预算记失败。非有限状态、API/仿真异常归为运行错误。固定臂超限不可重试。

L1-01 启用失败复位：抓持抬升后连续 0.25 s 不满足双指接触、且未形成有效持握插入后的释放，或未持握的圆柱连续 0.25 s 倾斜至少 60°，本次尝试失败；跌落至桌面下 10 cm 立即失败。检查按控制周期进行。短暂接触抖动、仍在手中主动调整姿态，以及有效插入后松爪落座不触发上述复位。

失败立即中断当前动作，公共执行循环清空旧动作目标，复位物体和两臂，重新完成准备动作，再向 GPT 提供新画面及 `attempt_reset` 通知。保留文字历史，调用次数、控制步和墙钟预算不重置；预算不足时直接结束。接触和物体真值仅用于评分/复位触发，不作为模型力觉输入。所有尝试和录像均保留，分别记录首轮结果、失败次数及最终结果；这是保留历史的重试协议，不能当成独立回合成功率。

L1-02～L1-08 保留原有恢复条件：普通掉落可在预算内自主恢复；掉至桌面下 10 cm 终止。工具抓错后必须重新形成正确柄部抓取证据。

修改阈值、资产、种子、提示、模型或执行参数都会改变实验条件；比较结果时保存并核对配置、版本和种子列表。自动复位不包含自动抓取、对准或插入动作；这些仍由模型决定。

## 安装与启动

Windows 和 Linux 使用同一份任务配置。各机器只在被 Git 忽略的 `configs/runtime/local.toml` 指定 Isaac Sim Python 和缓存/输出目录；模型地址及模型 ID 在 `configs/models/gpt.toml`，密钥使用该文件指定的环境变量。沿用项目现有 R5、相机资产和 Isaac Sim 环境。

在仓库根目录执行，Windows 将 `python3` 换成 `python`：

```bash
# L1-03/05：下载固定版本外部任务资产；L1-01 不需要此步骤。
python3 tools/fetch_l1_assets.py

# 如下载必须走代理，显式提供本机代理地址。
# python3 tools/fetch_l1_assets.py --proxy http://127.0.0.1:7890

python3 tools/launch.py list

# 仅检查配置与占位流程，不启动仿真或模型。
python3 tools/launch.py inspect L1-01
python3 tools/launch.py dry-run L1-01

# 正式运行：模型环境变量已设置后启动。
python3 tools/launch.py run L1-01 --gui
python3 tools/launch.py run L1-02 --gui
python3 tools/launch.py run L1-03 --gui
python3 tools/launch.py run L1-04 --gui
python3 tools/launch.py run L1-05 --gui
python3 tools/launch.py run L1-06 --gui
python3 tools/launch.py run L1-07 --gui
python3 tools/launch.py run L1-08 --gui
```

每条 `run` 命令运行一个任务。去掉 `--gui` 在后台运行；`--model-config` 可以选择另一份本机模型配置。Linux 如果使用自己维护的 shell 格式 `.env`，需先在当前终端用 `set -a`、`source .env`、`set +a` 导入，启动器不自动读取它；不要提交密钥。

任务参数在 `configs/tasks/l1_*.toml`。可复制成被忽略的 `*.local.toml` 修改种子或缩小调试预算，再通过 `--config` 指定；`task.id` 必须仍与所选任务相同。正式对比应使用约定的共享配置。

结果位于运行时配置的输出目录，默认 `runs/`。查看 `result.json` 的 `success`、`task_evaluated`、终止原因和分项指标；`episode.jsonl` 保存决策、反馈及评分；`scene.json` 保存实际几何、源文件哈希、初始姿态和评分参数；`video/` 保存三路录像。运行产物与下载的二进制资产不提交 Git。

## 工程检查与验证边界

唯一手动全链路集成用例仍是 `check gpt-pick-place`，它会启动 Isaac Sim 并调用真实模型；八项 L1 通过 `run L1-01`～`run L1-08` 进入同一框架，不新增脚本完成任务的入口。

离线回归使用 `python -m unittest discover -s tests -v`，不调用真实 GPT。包括 L1 几何与过程评分、右臂角色、准备阶段及公共执行流程；USD 几何检查在具备 USD 库和下载资产时执行。

2026-09-30 的 v3 验证：Windows/WSL 的 247 项测试套件通过，分别跳过 7/2 项环境依赖测试；Isaac Sim 中实际初始化和三路 RGB-D 采集通过。被动物理检查确认中心及偏心 9 mm 时可落座至约 20 mm 深度，并由孔座承重；两端对调也满足几何条件，孔外放置未通过。圆柱从倾斜 15° 的静止初态恢复直立；倒伏被评分器判为可复位失败，重新复位后评分恢复运行状态。已核对绑定材质及摩擦合成规则。离线回归还覆盖动作执行中掉落中断、历史和预算保留、接触抖动与正常释放免复位。这些是工程验收，不是 GPT 抓取插孔成功率；本轮未调用真实模型。

历史试管版曾修复源孔架 USD 的过期包围盒；导入器保留该回归检查。当前 L1-01 已替换任务几何和评分，历史试管结果不适用于本版。

[历史场景验证](l1_validation.md) 和 [历史执行器实验](l1_motion_fix.md) 记录了合并前的条件，不代表当前公共流程已完成 GPT 成功率评测。当前 RGB-D、可移动观察臂和执行方式不同，结果必须按实际版本分别统计。
