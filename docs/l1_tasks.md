# L1 刚性操作任务：l1-rigid-v1

目标是在固定传感器、动作接口和运动执行器条件下，评估 GPT 的视觉理解、空间判断、操作决策与失败恢复。实现依据飞书任务文档第 111 版的 L1-01～L1-08；L1-09 不在本轮范围。下列尺寸和阈值是本项目的工程基线，并非飞书文档规定的数值。

当前八项任务统一使用 `lab_room_v1` 室内环境和 `r5_black_silver_v1` 机器人外观。
其背景、材质和照明构成新的观测条件；比较实验时须固定这两个配置，不能与旧白底
场景直接合并统计。资产来源、启动与恢复旧外观的方法见 [场景外观说明](simulation_appearance.md)。

## 固定条件与信息边界

- 默认三路 RGB：`overview`、`left_wrist`、`right_wrist`，沿用 `r5_orbbec_provisional.toml`。合并后共享链路支持显式启用 RGB-D 和像素深度查询；L1 默认配置仍为 RGB 对照，不引入检测器、分割或物体真值输入。启用深度必须统一八项任务的观测条件并另行记录。
- 动作接口仍为 `sparse_eef`，R5 仿真配置、关节执行器和 12～70 mm 夹爪范围相同。八项任务统一使用 `cartesian_linear_v1` 和 `open_before_motion`，逐点 IK 已统一接入同事的 **Lula**，不再使用原自编数值逆解。保留速度、关节跳变和桌面碰撞检查；见 [运动修复说明](l1_motion_fix.md) 和 [分支集成记录](l1_integration.md)。旧 IK、旧执行方式与当前版本不能作为相同执行条件合并比较。
- 物理步长 1/240 s、控制步长 1/12 s，默认最多 40 次模型决策、2400 个控制周期、1800 s 墙钟时间。模型调用期间仿真暂停的行为沿用 master。
- 夹爪完成协议统一为 `stall_aware_v1`：闭合稳定受阻可结束动作但不代表抓取成功；相同目标开口用于保持夹持，先开夹受阻会取消排队运动并返回策略。协议和验证见 [抓放基线说明](l1_grasp_baseline.md)，不可与旧 `position` 结果当作相同执行条件比较。
- 八项均使用左臂，右臂保持初始姿态。改变参与臂需要新的布局版本，当前配置会拒绝直接切换右臂。
- `startup_pose="downward_ready_v1"` 在 GPT 首次决策前执行固定准备动作：TCP 移至相对基座 `(0.36, 0, 0.21)` m 的位置并垂直朝下，当前左臂配置对应世界 `(0.36, 0.42, 0.25)` m；保持原夹爪开口。准备动作不读取工件位置、不计入模型动作／决策数，单独录像和记录；消耗控制步与墙钟预算。到位后才开始任务评分并采集 GPT 首组观测。可设为 `none` 关闭，但属于不同实验条件。
- GPT 只收到任务文字、RGB、机器人实测状态和执行反馈；物体位姿、目标位姿、接触点和成功判断只进入评分与日志，不进入模型提示或动作目标生成。
- 相机初始姿态下腕部画面不一定包含工件。GPT 可以通过同一动作接口移动手腕主动观察；不会由脚本追踪工件或自动对准相机。
- 无吸附、自动抓取、自动插入、执行期间物体位姿写入或预设完成轨迹。

`specs.py` 定义形状和任务目标；`scene.py` 负责构建、复位和测量；`evaluation.py` 独立评分；`task.py` 接入既有执行循环。模型客户端与动作格式沿用 master；公共机器人适配器增加目标插值和夹爪时序，执行循环记录超时取消状态。任务评分器不参与生成路径。

## 复位与评分

每次复位使用 `[runtime].seed`，各物体起点 XY 默认抖动 ±8 mm、偏航 ±0.15 rad；夹具位置固定。相同种子复现相同初始布局，不承诺跨操作系统的 PhysX 轨迹逐位相同。

每个操作物体都必须出现持续至少 0.25 s 的双指接触，且物体中心比初始位置升高至少 15 mm。接触力阈值为每指 0.05 N。这样只推入目标或工程检查直接设置目标位姿不会算完整任务成功。

需释放的任务要求双指无有效接触、夹爪实测宽度至少 60 mm，并且 TCP 与物体包围盒间距至少 65 mm。指令要求打开到 70 mm。各目标同时满足以下条件持续 1 s 才成功：

- 目标几何成立、抓取抬升过程证据成立、释放条件成立（L1-05 除外）。
- 物体线速度不超过 0.02 m/s、角速度不超过 0.2 rad/s。
- 非参与臂相对评估起点的最大关节漂移不超过 0.01 rad。

插入类默认 XY 误差不超过 3 mm、高度误差不超过 4 mm、姿态误差不超过 0.14 rad。试管轴向旋转不影响判断，但倒插失败；积木条纹允许 180° 对称。工具和积木采用 10 mm 平面位置容差。环还要求挂钩位于环孔内且挂钩接触合力至少为环重量的一半。薄片检查跨越狭缝平面的角点轨迹和最终整体容纳状态。

`goal_complete` 与 `process_constraints_met` 分开记录。模型宣称完成不代表成功；未完成即停止或用尽预算记失败。掉落、抓错工具工作端、执行超时与动作拒绝均有记录，任务仍可在预算内恢复；物体跌落到桌面下 10 cm 或非参与臂超限则终止。非有限状态、API/仿真异常归为运行错误。工具抓错后必须重新形成正确柄部抓取证据。

修改阈值、资产、种子、提示、模型或执行参数都会改变实验条件；比较结果时保存并核对配置、版本和种子列表。这里没有将一次冒烟测试当作成功率统计，也未增加用于特定错误的自动恢复策略。

## 安装与启动

Windows 和 Linux 使用同一份任务配置。各机器只在被 Git 忽略的 `configs/runtime/local.toml` 指定 Isaac Sim Python 和缓存/输出目录；模型地址及模型 ID 在 `configs/models/gpt.toml`，密钥使用该文件指定的环境变量。沿用项目现有 R5、相机资产和 Isaac Sim 环境。

在仓库根目录执行，Windows 将 `python3` 换成 `python`：

```bash
# 首次运行：下载固定版本外部资产；已有文件会验证 SHA-256。
python3 tools/fetch_l1_assets.py

# 如下载必须走代理，显式提供本机代理地址。
# python3 tools/fetch_l1_assets.py --proxy http://127.0.0.1:7890

python3 tools/launch.py list

# 不调用模型的场景检查；会自动完成并退出。
python3 tools/launch.py check l1-scene --config configs/tasks/l1_01_cylinder_insertion.toml --gui

# 复测原先卡住的首步与第二步、夹爪时序、桌面穿入拒绝。
python3 tools/launch.py check l1-motion --gui

# 不调用 GPT：两次物理抓放与一次张开夹爪的负例。
python3 tools/launch.py check l1-grasp --gui

# 正式运行：模型环境变量已设置后启动。
python3 tools/launch.py run L1-01 --gui
python3 tools/launch.py run L1-02 --gui
python3 tools/launch.py run L1-03 --gui
python3 tools/launch.py run L1-04 --gui
python3 tools/launch.py run L1-05 --gui
python3 tools/launch.py run L1-06 --gui
python3 tools/launch.py run L1-07 --gui
python3 tools/launch.py run L1-08 --gui
```

每条 `run` 命令运行一个任务。去掉 `--gui` 在后台运行；`--model-config` 可以选择另一份本机模型配置。Linux 如果使用自己维护的 shell 格式 `.env`，需先在当前终端用 `set -a`、`source .env`、`set +a` 导入，启动器不自动读取它；不要提交密钥。

任务参数在 `configs/tasks/l1_*.toml`。可复制成被忽略的 `*.local.toml` 修改种子或缩小调试预算，再通过 `--config` 指定；`task.id` 必须仍与所选任务相同。正式对比应使用约定的共享配置。

结果位于运行时配置的输出目录，默认 `runs/`。查看 `result.json` 的 `success`、`task_evaluated`、终止原因和分项指标；`episode.jsonl` 保存决策、反馈及评分；`scene.json` 保存实际几何、源文件哈希、初始姿态和评分参数；`video/` 保存三路录像。运行产物与下载的二进制资产不提交 Git。

## 工程检查与验证边界

`check l1-grasp` 验证共享执行器对 40 mm 方块的物理抓取、搬运和释放，已在本机通过两次正例与一次负例。它不使用八项任务的完成目标，不能证明各工件均可完成；详见 [独立基线与夹爪反馈](l1_grasp_baseline.md)。

`check l1-scene` 依次检查初始场景不成功、三路 RGB 有图像、接触测量可读、夹具容纳目标后保持稳定、同种子复位一致。它会**直接设置一次目标位姿**检查夹具；明确记录 `task_evaluated=false`、`success=null`，且验证这一操作不能骗过正式过程评分。它不能证明机械臂完成了抓取或插入。

加 `--gui` 后，检查完成会保存结果、恢复初始布局并暂停仿真，窗口一直保留供自由查看；
在启动终端按 `Ctrl+C` 或关闭窗口退出。查看期间不受检查超时限制，也不继续评分。
不加 `--gui` 时检查完成自动退出。

L1-01 还用仅存在于工程检查中的 6 mm 小方块检验孔架上沿的真实物理支撑。2026-09-29 修复了源 USD 的过期包围盒：原包围盒比实际顶点尺寸大约 100,000 倍，导致视觉和碰撞几何被错误缩小。导入器现在从实际顶点重算包围盒，仅覆盖运行场景，不修改下载资产。孔架实际尺寸为 246×115.2×60 mm，试管目标中心高度校正为 64.5 mm。此前孔架异常的运行结果不可作为正常插孔实验结果；修复未放宽评分容差。

离线回归使用已经安装本项目的 Python 环境执行：

```bash
python -m unittest discover -s tests -v
```

本机开发环境也可通过 `PYTHONPATH=src` 运行源码中的测试。记录见 [验证结果](l1_validation.md)。目前完成 Ubuntu / Isaac Sim 5.1 场景验证；Windows 实机 GPU 验证和八项任务的多种子 GPT 完整测评尚未执行。相机仍采用 master 的临时未标定参数；新执行器插值笛卡尔目标并检查已知桌面，实际轨迹仍有跟踪误差，也不会自动绕开工件或夹具。本版本不包含力控或真实硬件插接验证。
