# L1 执行器抓放基线与夹爪完成反馈
> 历史记录：以下是 master 合并前的实现与验证条件。当前采用统一 RGB-D 流程、右臂观测和 100 次默认预算，仅保留 GPT 抓放集成用例；本文旧配置开关和检查命令不再适用。当前使用说明见 [L1 任务](../l1_tasks.md)。

此检查先验证执行器能通过物理接触抓放，再进入 GPT 实验。它使用已知几何的 40 mm、80 g 方块，复用 L1 的 R5、三路 RGB、关节驱动、笛卡尔插值和垂直向下准备姿态。不调用 GPT，不代表八项 L1 工件已经完成，也不进入 GPT 成功率。

## 启动

在仓库根目录执行，Windows 将 `python3` 换成 `python`：

```bash
python3 tools/launch.py check l1-grasp --gui
```

去掉 `--gui` 可后台运行。沿用各机器 `configs/runtime/local.toml` 中的 Isaac Sim Python 配置，无需 API Key。配置在 `configs/checks/l1_grasp.toml`。

依次运行两次左臂抓放与一次张开夹爪的负例，自动退出。每次均复位；右臂保持初始姿态。完整流程为：固定准备姿态 → 张开 → 接近 → 下降 → 单独闭合 → 抬升 → 横向搬运 100 mm → 降低 → 张开 → 撤离。

工程脚本使用已知起点、尺寸和终点生成动作；执行期间通过 IK、关节位置驱动和接触摩擦搬动物体，不写物体位姿、不添加吸附约束。物体位姿仅在复位时设置。正式 L1 策略不调用此脚本，也不接收它的物体真值。

## 独立物理判定

- 抬升及搬运后各保持 1 s：物体始终高于初始中心至少 70 mm，且采样中存在双指接触。控制器返回 `completed` 本身不能通过检查。
- 放下并释放后稳定 1 s：平面位置误差 ≤25 mm、高度误差 ≤6 mm、线速度 ≤0.02 m/s、角速度 ≤0.2 rad/s；双指无有效接触、开口 ≥67 mm、TCP 撤离超过 70 mm。
- 负例：保持张开执行抬升，物体必须未通过抬升判定且位移 <10 mm。
- 右臂最大关节漂移 ≤0.01 rad。

结果写入 `runs/L1_grasp_<时间>_<标识>/`：`result.json`、`report.md`、`grasp.jsonl`、配置与源码哈希、场景记录和三路 `video/<camera>/motion.mp4`。`passed` 表示工程检查通过；始终明确记录 `task_evaluated=false`、`success=null`、`gpt_called=false`。

## 夹爪协议：stall_aware_v1

八项 L1 和四份 GPT 单臂抓放共享配置启用：

```toml
[execution]
gripper_completion = "stall_aware_v1"
```

旧配置未填写时仍使用 `position`，要求到达指定开口。新设置改变实验执行条件，比较模型结果时必须保持一致。

1. 夹爪闭合遇到物体时，通常不能到达比物体更窄的目标开口。新协议跟踪实测手指位置：在 0.5 s 内变化不超过 0.25 mm、且仍有闭合位置误差时，返回 `closing_stalled`。物理接触求解器的瞬时速度抖动不会使闭合永久等待；容忍该抖动还要求机械臂关节在 0.5 s 内稳定于 0.003 rad 范围，原有 TCP 和关节到位容差继续生效。
2. `closing_stalled` 只表示稳定受阻。`gripper_reached=false`、`grasp_confirmed=null`，既可能夹住物体，也可能碰到桌面或夹具。GPT 仍需结合 RGB 和小幅试抬确认；独立评分器仍检查真实物体过程。
3. 搬运命令重复相同的**目标开口**时保留原夹爪驱动，不因实测开口偏差误判为重新张开，也不排队等待第二次闭合。
4. 真正要求先张开再移动、但张开稳定受阻时，返回 `blocked`，取消排队的机械臂轨迹并保持实测关节位置，立即把控制权交回策略。等待不会恢复旧轨迹；策略可以显式发送只移动机械臂的撤离动作，或新的夹爪命令。不会自动生成恢复路线。

闭合与抬升应分成两条动作：组合动作的首次闭合仍在机械臂到位后执行，不能把它当作自动抓取技能。单独张开而未到位时仍使用原有动作预算和超时反馈。
